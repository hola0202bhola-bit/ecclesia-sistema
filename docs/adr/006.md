# ADR 006 — Identidad local y sesiones revocables

Estado: aplicado como incremento técnico autorizado por el alumno el 1 de noviembre de 2026. Amplía ADR 004 sin inventar respuesta a PC19/G7. P092/P093 ya autorizan roles y ámbito; la falta de política de bootstrap no obliga a dejar toda autenticación sin implementar.

Se conserva Express/TS/Prisma/PostgreSQL/EJS. Módulo Identidad por capas y principal compartido en shared/domain; composición conecta Identidad e Iglesias sin importaciones entre módulos. Migración aditiva con FK de iglesia, CHECK de rol/ámbito, identificador normalizado único y sesiones. No modifica migración anterior ni elimina datos de iglesias.

Contraseña con bcryptjs 3.0.3 fijado en lock, costo 12, mínimo 15 caracteres y máximo 72 bytes UTF-8 sin truncar. P130 permite bcrypt o argon2: se elige bcrypt en JS sin binarios adicionales para Windows. Argon2id sería alternativa; no se sustituye la obligación escrita por scrypt. Solo se guarda el hash. Fuente primaria: [bcrypt.js](https://github.com/dcodeIO/bcrypt.js); parámetros y límite contrastados con [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Sesión JWT HS256 1h con subject/jti/issuer/audience/exp y registro PostgreSQL. JWT no contiene roles autoritativos: cada petición obtiene cuenta activa, rol y ámbito actuales desde BD. Logout elimina solo esa sesión, tanto para bearer API como para cookie de la web. El adaptador JWT externo histórico permanece probado en modo explícito de compatibilidad, deshabilitado en standalone. No se promete revocación de tokens externos.

Web: cookie HttpOnly/SameSite=Strict, Secure al configurar origen HTTPS, token CSRF por sesión y coincidencia exacta Origin para escrituras con cookie. Login de formulario exige Origin para evitar login CSRF. API login responde bearer sin instalar cookie; no admite rol/ámbito del cliente. No se habilita CORS. Referencias: [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) y [CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

Un rol por cuenta y una iglesia para ADMIN_IGLESIA/TESORERO. Coordinación sin iglesia. Es una restricción de este incremento, no prohibición docente. Alta/listado por Coordinación; no hay registro público. Se posponen acumulación de roles, cambio de asignación, recuperación, desactivación vía UI y reglas de último coordinador. Activo permite rechazar cuentas deshabilitadas en BD, sin exponer aún una nueva política de edición.

Primera cuenta: comando local interactivo, password oculto y confirmación; no recibe contraseñas por argumentos ni crea usuario automático en migración/seed. Solo permite inicialización cuando la tabla está vacía, con advisory lock transaccional para dos ejecuciones concurrentes. Alternativa descartada: contraseña predeterminada o bootstrap HTTP. Esta provisión es reversible y no acredita un proceso de alta aprobado por el cliente.

Límite de login acotado en memoria: 10 intentos/IP/15min, antes de bcrypt y compartido entre formulario/API dentro del proceso. Sin bloqueo permanente de cuentas; contador distribuido y recuperación futura. Aplicación enlazada a 127.0.0.1, como antes; publicar requiere configuración real HTTPS/origen. Las pruebas documentadas miden comportamiento local y no declaran seguridad productiva completa.
